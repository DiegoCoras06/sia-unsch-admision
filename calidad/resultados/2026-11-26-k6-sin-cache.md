# k6 hasta 2000 usuarios sin caché de contenidos — 26/11/2026

## Objetivo

Repetir la carga que falló el 20/11/2026 con las cachés de catálogo y contenido completamente desactivadas, manteniendo
la API en la computadora del equipo y PostgreSQL en RDS Ohio.

## Mejora aplicada

Se implementó **request coalescing / single-flight**. Cuando varias solicitudes idénticas llegan mientras una consulta a
PostgreSQL está en curso, todas esperan esa misma promesa. Al terminar, la promesa se elimina inmediatamente: no se
conservan filas, DTO ni respuestas y la próxima solicitud vuelve a consultar RDS.

Por tanto, el escenario sigue ejecutándose con:

```text
CATALOG_CACHE_TTL_MS=0
CONTENT_CACHE_TTL_MS=0
```

Esto no es una caché de contenidos: evita trabajo simultáneo duplicado, pero no responde lecturas futuras con un valor
anterior. Las pruebas unitarias verifican que dos llamadas concurrentes comparten la consulta y una llamada posterior
vuelve a ejecutar el origen.

## Comandos

En una terminal:

```powershell
npm run dev:rds:no-cache
```

En otra:

```powershell
k6 run calidad/k6/carga-2000.js
```

La causa anterior no era la complejidad de la consulta, sino repetir el mismo trabajo miles de veces a través de una
conexión intercontinental y un pool de cinco conexiones. Single-flight mantiene frescura total y limita cada clave a una
consulta activa.

## Alcance

La prueba demuestra que una instancia Node puede absorber la concurrencia sin caché de contenidos. En un despliegue con
varias instancias, single-flight actúa dentro de cada proceso; CloudFront sigue siendo la estrategia recomendada para
tráfico público y la prueba debe repetirse desde AWS para eliminar la latencia Perú–Ohio.
