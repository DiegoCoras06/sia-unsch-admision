# Evidencia de pruebas End to End — 26/11/2026

## Resultado

**APROBADO**. La suite se ejecutó con `npm run test:e2e` sobre un entorno completamente aislado:

- PostgreSQL 16 embebido en el puerto 5435;
- API Express en el puerto 3100;
- frontend Angular en el puerto 4300;
- Microsoft Edge en modo headless mediante Playwright;
- proveedores de identidad y pago simulados, sin acceder a RDS ni realizar cobros.

## Escenario automatizado

El flujo cubre las capas frontend, API y base de datos:

1. consulta de un DNI sintético y autocompletado de nombres;
2. ingreso y validación de datos personales, contacto y procedencia;
3. carga y recorte de la fotografía a 240 × 320;
4. selección de Ingeniería de Sistemas y cálculo de la tasa de S/ 250.00;
5. aceptación de declaraciones y registro de la inscripción;
6. generación del código de postulante;
7. consulta posterior con DNI y código;
8. rechazo de una segunda inscripción con el mismo DNI.

## Salida obtenida

```text
✔ DNI 99900021 autocompletó: GUTIÉRREZ MENDOZA MARÍA ELENA
✔ Foto recortada a 240 × 320 en el navegador
✔ Resumen en vivo: Ingeniería de Sistemas, S/ 250.00
✔ Inscripción registrada con código 27000017
✔ Consulta con DNI + código muestra la orden de pago
✔ El mismo DNI ya no puede volver a inscribirse
E2E inscripción: OK
```

La ejecución local guarda el reporte detallado y las capturas en `.e2e-artifacts/`. GitHub Actions conserva esa carpeta
como el artefacto `evidencia-e2e` durante 30 días, incluso cuando la prueba falla.

## Automatización

El trabajo `E2E (PostgreSQL + API + Angular)` de `.github/workflows/ci.yml` se ejecuta en cada `push` y `pull_request`
a `main`. La base E2E utiliza un directorio y credenciales exclusivos; nunca lee `DATABASE_URL` ni secretos del entorno.
